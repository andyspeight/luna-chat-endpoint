# Templates

Copy these shapes when writing the persisted artifacts. All three live in `.claude/qa/` (a sibling of the skill folder, so the skill folder stays a clean copyable template). Create `.claude/qa/` if it doesn't exist.

---

## `.claude/qa/PROJECT_CONTEXT.md`

Written/refreshed in Sweep 0. This is the brain of every run — it makes the pass concept-aware instead of a generic sweep. Keep it current; a human may edit it to correct or add invariants.

```markdown
# Project Context — <project name>
_Generated by qa-sentinel on <date>. Edit freely; the skill reads this every run._

## What this project is
<one paragraph, plain language: what it does, who uses it>

## Stack & toolchain
- Language(s)/framework(s): <…>
- Runtime / package manager: <…>
- Build command: <…>
- Type check: <…>
- Lint: <…>
- Tests: <…>
- Dependency audit: <…>
- Deploy target: <…>

## Trust boundaries
- Server-side (may hold secrets): <files/dirs>
- Client-shipped (public): <files/dirs/bundle output>

## Sensitive assets
- Secrets/keys: <which, where they should live>
- PII: <what, where>
- Money/payments: <…>
- Paid-per-call APIs (budget risk): <…>
- Write access to data: <…>

## Attack surface (public/anonymous entry points)
- Routes/endpoints: <…>
- Forms / user input: <…>
- Webhooks / callbacks: <…>
- File uploads: <…>
- User-generated content rendered to DOM: <…>

## Critical invariants (must never happen)
- <e.g. no secret reaches the client bundle>
- <e.g. a user can never read another tenant's records>
- <e.g. a price/total is never trusted from client input>

## Notes / known context
- Installed project skills this pass defers to: <e.g. acme-security>
- Anything unusual the next run should know: <…>
```

## `.claude/qa/QA_REPORT.md`

Overwritten each run (latest only). Direct, priority-ranked, actionable.

```markdown
# QA Sentinel Report — <project name>
_Run <date> · <N> rounds · stopped because <reason>_

## Verdict
**SHIP | SHIP WITH NOTES | DO NOT SHIP** — <one line why>

## Headline risks
1. <most severe finding, one line>
2. <…>

## Fixed this run
### P0
- `<file>` — <what was wrong → what changed> · verified by <success signal>
### P1
- <…>
### P2
- <…>

## Needs your decision  (not auto-fixed)
- **[Pn] `<file>`** — <finding>. Recommendation: <specific recommendation>. Why not auto-fixed: <reason>.

## Residual risk
- <what still stands and why>

## Run stats
- Rounds completed: <N> / cap
- Baseline → final: build <…>, tests <…>, lint <…>, audit <…>
- Findings: <P0/P1/P2/P3 found> · fixed <…> · flagged for human <…>
- Loop stopped because: <no new fixable findings | round cap | only human items | no net progress>
```

## `.claude/qa/QA_LOG.md`

Append one line per run (newest at the bottom). Lets trends show across runs.

```markdown
# QA Sentinel Log
| Date | Rounds | P0 fixed | P1 fixed | P2 fixed | P0/P1 remaining | Verdict |
|------|--------|----------|----------|----------|-----------------|---------|
| 2026-06-26 | 3 | 1 | 4 | 6 | 2 (human) | SHIP WITH NOTES |
```
