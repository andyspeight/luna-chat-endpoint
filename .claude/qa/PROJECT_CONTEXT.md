## What this project is
Luna Chat is a multi-tenant live-chat + AI assistant platform for travel agencies
(Travelgenix / "Travelify" brand). It ships an embeddable website chat widget, an
agent dashboard, an AI "copilot" that drafts grounded replies, a knowledge/"brain"
pipeline that scrapes and re-verifies travel information (FCDO advice, events,
places), and an omnichannel WhatsApp inbox. It runs as Vercel serverless functions
with Airtable as the system of record, Ably for realtime, Anthropic for the LLM, and
Vercel Blob for file uploads.

## Trust boundaries
- Server-side (may hold secrets): everything under `api/` and `lib/` — Vercel
  serverless, holds `ANTHROPIC_API_KEY`, `AIRTABLE_KEY`/`AIRTABLE_PAT`, Ably keys,
  `ADMIN_PASSWORD`, WhatsApp provider tokens, webhook signing secrets.
- Client-shipped (public): everything under `public/` — `widget-core.js`,
  `dashboard.html`, `dashboard-copilot.js`, etc. Anything here is public.

## Sensitive assets
- Secrets/keys: ANTHROPIC_API_KEY (cost), AIRTABLE_KEY/PAT (full base read/write),
  Ably API keys (realtime), ADMIN_PASSWORD, WhatsApp provider tokens, webhook verify/signing secrets.
- PII: visitor chat transcripts, names, emails, phone numbers (WhatsApp), conversation history.
- Money/payments: no direct card handling seen, but travel content (prices, ATOL/ABTA refs) is liability-sensitive.
- Paid-per-call APIs (budget risk): Anthropic (luna-chat, luna-copilot, reverify, scan, translate, quality), WhatsApp send, Foursquare/Ticketmaster/search.
- Write access to data: Airtable client table (create/update clients), conversation logs, knowledge base.

## Attack surface (public/anonymous entry points)
- Routes/endpoints: 33 functions under `api/`. Public/anon-facing include
  `luna-chat`, `widget`, `widget-config`, `subscribe`, `whatsapp-webhook` (Meta callback),
  `ably-token` (visitor path), `translate`, `scan-page`, `upload`, `email-chat-transcript`,
  `log-conversation`, `visitor-history`, `global-brain`.
- Admin/privileged: `clients`, `auth`, `auth-session`, `profile`, `monitor`, cron jobs
  (`reverify*`, `refresh-fcdo`, `discover-scan`, `knowledge-freshness`, `fcdo`).
- Forms / user input: widget chat messages, subscribe form, onboarding, copilot prompts.
- Webhooks / callbacks: `whatsapp-webhook` (Meta Cloud API / 360dialog / Gupshup).
- File uploads: `upload.js` (Vercel Blob).
- User-generated content rendered to DOM: chat transcripts in dashboard + widget; scraped knowledge.

## Critical invariants (must never happen)
- No secret (Anthropic/Airtable/Ably/admin/WhatsApp) ever reaches the client bundle in `public/`.
- A client/agent can never read or write another tenant's data (Airtable records scoped by AuthClientId/role).
- The admin endpoints (`clients`, etc.) must never be reachable without a real secret — no hardcoded fallback password in production.
- An anonymous visitor can never drain the Anthropic/WhatsApp budget (rate + cost caps on paid-call endpoints).
- The WhatsApp webhook must verify provider signatures before acting on events.
- Visitor input is always data, never spliced into the LLM system prompt.
- User-supplied content rendered to the DOM is escaped/sanitised (no stored XSS).
